ให้ผู้ใช้กำหนดสัญลักษณ์ความสัมพันธ์ ER เองได้

ออกแบบแผงขวาตอนคลิกเส้น FK หรือคอลัมน์ FK มี 3 แบบ ตัวอย่างด้านล่างเล่นได้ กดที่แบบไหนก็ได้ ภาพตัวอย่างในทุกแบบเปลี่ยนตามกัน

ตอนนี้โปรแกรมอนุมานเอง (ตัวเลือก "อัตโนมัติ")

ส่วนของเส้นอ่านจากผลที่วาด
ฝั่งแม่FK เป็น NOT NULL หรือ PKใช่ = หนึ่งเดียว · ไม่ใช่ = ศูนย์หรือหนึ่ง
ฝั่งลูก จำนวนFK เป็น UNIQUE เดี่ยว ๆใช่ = หนึ่ง (1:1) · ไม่ใช่ = หลาย (ตีนกา)
ฝั่งลูก ขั้นต่ำไม่มีข้อมูลให้อ่านเป็นศูนย์เสมอ (0..N / 0..1)

ที่ผิดจากความจริงทางธุรกิจ เช่น "การจองต้องมีรายการอย่างน้อย 1" วาดไม่ได้ในตอนนี้ เพราะข้อมูลนี้ไม่อยู่ในสคีมา

ลองสมมุติ FK ตัวอย่าง orders.customer_id → customers.id

ค่าสองช่องนี้คือสิ่งที่ "อัตโนมัติ" ใช้ตัดสิน ปรับดูว่าเมื่อผู้ใช้เลือกสัญลักษณ์ที่ขัดกับสคีมา แต่ละแบบเตือนอย่างไร

กติกาที่ใช้ร่วมกันทั้ง 3 แบบ

เป็นเอกสาร ไม่แตะ SQL

ค่าที่ผู้ใช้เลือกบันทึกในความสัมพันธ์นั้น (ฟิลด์ใหม่ เข้ากันได้ย้อนหลัง ไฟล์เก่าอ่านเป็นอัตโนมัติ) ใช้กับแคนวาส PNG SVG พจนานุกรมข้อมูล และ HTML ส่วน DDL ไม่เปลี่ยน

เตือนเมื่อขัดกับสคีมา

เลือก "หนึ่ง" ทั้งที่ FK ไม่ UNIQUE หรือ "หนึ่งเดียว" ทั้งที่ FK เป็น NULL ได้ จะขึ้นแถบเหลือง พร้อมปุ่มแก้สคีมาให้ตรง (ตั้ง UNIQUE / NOT NULL) ผู้ใช้เลือกเองว่าจะกด

ขั้นต่ำของฝั่งลูกเป็นเอกสารล้วน

"ต้องมีลูกอย่างน้อย 1" ฐานข้อมูลบังคับด้วย FK ไม่ได้ จึงแสดงเป็นสัญลักษณ์และขึ้นข้อความว่าต้องบังคับที่ฝั่งแอปหรือทริกเกอร์ ไม่มีปุ่มแก้สคีมา
